# 資産管理シートの週次更新（Google Apps Script）

スプレッドシート「お金関連」のシート7（口座 × 日付の残高マトリクス）に、
毎週自動で新しい日付列を追加するスクリプト。

## 何をするか

1. 最新の記録列の右に1列追加する
2. 前回列を数式・書式ごとコピーする
3. 年行・日付行を実行日で上書きする

前回列をコピーするので、小計行や合計行の数式は相対参照が調整されて新しい列を集計する。
各口座のセルには前回の残高が入った状態になるため、**変動した口座だけ上書きすればよい**。

これは既存シートの実害も潰す。現状は毎回すべての口座を埋めているわけではなく、
埋めなかった口座は空欄のまま残る。前回値が引き継がれないため、
その列で全カードが空欄だと小計が 0 になっていた（実際に複数の列で発生している）。

## 導入手順

1. スプレッドシートを開き、`拡張機能` → `Apps Script`
2. 生成されたエディタに `asset-sheet-weekly.gs` の中身を貼り付ける
3. 上部の関数選択で `dryRun` を選んで実行

   初回は権限の承認を求められる。承認後、実行ログに検出結果が出る。

   ```
   {
     "年行": 3,
     "日付行": 4,
     "最初のデータ列": "F",
     "最後のデータ列": "BQ",
     "最後の日付": "7/18",
     "次に追加される列": "BR"
   }
   ```

   **「最後の日付」がシート上の最新列と一致しているか必ず確認する。**
   ズレていたらレイアウト検出が外しているので、この時点で止めること。

4. `addWeeklyColumn` を手動で1回実行し、列が意図どおり増えるか確認する
   （問題があれば `Ctrl+Z` ではなくシートの版履歴から戻す）
5. `installWeeklyTrigger` を1回だけ実行してトリガーを登録する

## 設定

`CONFIG` を編集する。

| キー | 既定値 | 内容 |
|---|---|---|
| `spreadsheetId` | 「お金関連」のID | 対象スプレッドシート |
| `sheetName` | `シート7` | 対象シート |
| `dateFormat` | `M/d` | 日付行の書式 |
| `yearPolicy` | `onChange` | 年行に年を入れる方針。`onChange` は年が変わったときだけ |
| `notifyEmail` | `''` | 列追加後の通知先。空なら送らない |

実行曜日・時刻は `installWeeklyTrigger` 内の `onWeekDay` / `atHour` を変更して再実行する。

## 注意

- 行や列の位置はハードコードしていない。日付行は「`m/d` 形式のセルが5個以上並ぶ行」、
  年行はその上の「4桁の年が2個以上並ぶ行」として検出する。
  シートの見出し構造を変えると検出条件を見直す必要がある。
- **小計行・合計行が数式ではなく直接入力された値の場合**、
  コピーで前回の数値がそのまま残り、実態とズレる。
  導入前にこれらの行が数式かどうか確認すること。
- `insertColumnAfter` はシート全体に列を挿入する。
  同じ行範囲に別の表が横に並んでいる場合は影響を受ける。

## 楽天証券（投資信託）の扱い

楽天証券はログイン追加認証を設定していると Moneytree と連携できない
（[Moneytree ヘルプ](https://help.getmoneytree.com/ja/) / 2025-05-14 時点で対応時期未定）。

**追加認証は解除しない。** 証券口座は出金も売買もできるため、
週1回の入力を省くために防御を下げる取引ではない。
楽天証券だけ手入力の例外として運用する。

前回列をコピーする作りなので、残高が動かなかった週は触る必要がない。
評価額が動いた週だけ上書きする。

### 該当する行

証券の行はシート7に既にある。名義別の4行と、その小計。

| 行 | キー | 内訳 | 毎週動くか |
|---|---|---|---|
| 58 | `資産/在庫/亮太` | NISA（積立中）＋ 保有投信 | 動く（積立 + 基準価額） |
| 59 | `資産/在庫/明子` | NISA（積立中）＋ 保有投信 | 動く（積立 + 基準価額） |
| 60 | `資産/在庫/結楓` | 保有投信のみ（積立なし） | 動く（基準価額のみ） |
| 61 | `資産/在庫/結依` | 保有投信のみ（積立なし） | 動く（基準価額のみ） |
| 62 | 小計 | | |

中分類の結合が「在庫」から続いているため、キーの中分類は `在庫` になる。
証券という中分類は存在しない。

NISA だけでなく証券口座の評価額全体が入る。

この4行は Moneytree で自動取得できないため、**CSV 取り込みを実装しても
上書き対象から除外する**こと。自動転記が手入力値を潰さないようにする。

**投資信託なので基準価額が日々動き、4行とも毎週必ず手入力が必要になる。**
他の口座のように「動かなかった週は触らなくてよい」は成立しない。
ここが自動化後に残る唯一の定常作業。

なお 58〜61 行は大分類・中分類の列が空欄で、他ブロックのような
`銀行` `フリマ` といったラベルが付いていない。C列に `証券` を入れておくと、
CSV 取り込みの実装時に対象行を名前で特定でき、行番号のハードコードを避けられる。

### 将来の選択肢：口数 × 基準価額での自動算出

手入力を消したい場合、シートに保有口数を持たせ、基準価額を自動取得して
掛け算する方式が取れる。追加認証を解除せずに済む。

- 60・61 行（結楓・結依）は積立が止まっており**口数が変わらない**ため、
  一度登録すれば以降は完全に自動化できる
- 58・59 行（亮太・明子）は積立で口数が増えるため、月1回の口数更新が必要

実装には銘柄（ファンド名）と保有口数が要る。国内投信は `GOOGLEFINANCE` が
非対応のため、基準価額は GAS で別途取得する。

## なぜ Moneytree なのか（マネーフォワード ME との比較）

集約サービスは Moneytree を使う。再検討しなくて済むよう根拠を残す。

**マネーフォワード ME は口座別の残高を CSV に出せない。** これが決定的。

| 出力 | 中身 | 可否 |
|---|---|---|
| ME / 家計簿データ | 収支明細。月ごとに1ファイル、残高列なし | ✗ |
| ME / 資産推移 | 日付 × 資産カテゴリ（預金・株式・投資信託…）の集計。口座別の内訳は出ない | ✗ |
| Moneytree Grow | 複数口座・カードを一括、残高列あり、最長2年 | ○ |

シート7は口座単位のマトリクスなので、カテゴリ単位の集計では粒度が足りない。
ME でも画面上は口座別に見られるが、書き出せないため転記の自動化に繋がらない。

楽天証券の追加認証は ME なら連携できる（Moneytree は不可）が、結論は変わらない。
上記のとおり ME は口座別残高を出力できないため、連携できても 58〜61 行の
手入力は消えない。料金も Moneytree Grow が月360円、ME プレミアムが月500円前後。

その他に検討して外した候補。

- **お金のコンパス** — 2024年6月末でサービス終了。選択肢にならない
- **Zaim** — 出力は家計簿（収支）データ。API が残高を返さず、連携口座のデータは
  API では取得できない仕様であることから、口座別の残高スナップショットを
  書き出せる見込みは薄い。プレミアムも月480円前後で Grow より高い

判定軸は一貫して「**口座別の残高スナップショットをファイルに書き出せるか**」。
家計簿アプリは「いくら使ったか」を出力する設計で、「今いくらあるか」を
口座単位で書き出せるものは少ない。Moneytree はそれができる。

なお API 経由の自動取得は断念した。銀行の個人向け API は電子決済等代行業者の
登録が必要で個人には開放されていない。カード会社に公開 API は無い。
Moneytree LINK API は残高取得に対応しているが、client_id / client_secret の
発行が法人契約前提。Zaim API は残高を返さない。CSV 出力が現実的な上限。

## 記録の基準：合計（未確定＋確定＋リボ）

シート7の負債は **合計基準** で記録する。以前は確定額（次回請求額）で
記録していたが、せどりでカード決済が大量に走るため、未確定分を除くと
債務が構造的に過小になる。

合計は「現時点でまだ払っていない総額」で、締め日に依存しない。
確定額は支払日がカードごとに違う数字の寄せ集めになり、締め日にジャンプして
支払日にゼロへ落ちるため、推移としては読みにくい。

**切り替えの段差**: 7/18 までの列は確定基準、それ以降は合計基準。
負債の推移に段差が出る。切り替えた最初の列にメモを残すこと。

### 引き落としリスク管理は別建て

合計値から確定額は復元できないため、「支払日までに口座へ入れておくべき額」は
別に確認する。確定額は締め日を過ぎたら支払日まで動かないので、月2回で足りる。
`payment-reminder.gs` がその通知を行う。

| | 目的 | 頻度 | 基準 |
|---|---|---|---|
| シート7 | 資産・負債の実態 | 週次 | 合計 |
| 支払い予定表 | 引き落としリスク管理 | 月2回 | 確定 |

## 残高の取り込み（import-balances.gs）

Moneytree の口座残高画面を見て「取込」シートに `口座名 / 金額` を貼り、
`importBalances()` で最新の日付列へ転記する。

Moneytree の個人向けプランは出力が「利用明細」で、口座別残高が
含まれるか未確認のため、画面の数字を使う方式にしている。
無料プランのままで足りる。

### スマホで完結させる前提

普段の運用はスマホから行う。スマホでは Apps Script のエディタも実行ログも
使えないため、次の2点で対応している。

- **貼った時点で自動転記される。** `installImportTrigger()` で登録する
  インストール型 onEdit トリガーが `onImportEdit` を呼ぶ。手動実行は不要
- **結果は取込シートの1行目に出る。** 成功なら緑、失敗なら赤で表示。
  実行ログを見られなくても成否が分かる

貼り方の揺れも吸収する。スマホのスプレッドシートは複数行テキストを
1セルにまとめて入れることがあるため、以下のいずれでも読める。

- A列に口座名、B列に金額（タブ区切りで貼った場合）
- A列の1セルに全行が改行区切りで入っている場合
- `hama-eco カード -¥1,496,810` のように名前と金額が空白区切りの場合

### 手順

セットアップはパソコンで1度だけ行う。以降の運用はスマホで完結する。

1. `createImportSheet()` を1度実行して「取込」シートを作る
2. `installImportTrigger()` を1度実行して自動転記を有効にする
3. 以降は Moneytree の口座残高から起こした「口座名 / 金額」を
   取込シートの3行目以降に貼るだけ。貼った時点で転記され、
   結果が1行目に表示される

### 転記したセルは赤字になる

どの数字が Moneytree 由来かを一目で分かるようにしている。

| 文字色 | 意味 |
|---|---|
| 赤 | その列が最新だったときに Moneytree から転記された値 |
| 黒 | 前回値の引き継ぎ、または手入力 |

前列をコピーすると文字色まで引き継がれるため、`addWeeklyColumn` は
追加した列の文字色を既定に戻す（`CONFIG.resetFontColor`）。
これがないと赤字が毎週伝播して意味を失う。

過去の列の赤字はそのまま残るので、「その週に実際に取得できていたか」の
記録になる。黒いままの行は更新されていないので、放置に気づける。

### 設計

- 行番号はハードコードせず、`大分類/中分類/項目` で行を引く。
  B列・C列が縦結合されている前提で、上の値を引き継いで解決する
- **マッピングに無い行には一切書き込まない。** 小計行の数式と、
  手入力する証券行（58〜61）はこれで保護される
- 複数の口座を1行に合算できる。楽天亮太は Visa と Mastercard の2枚あるが
  シートは `楽天（亮太）` 1行なので合算される
- 負債は Moneytree でマイナス表示、シートではプラス表記なので絶対値で書く
- `listRowKeys()` でシート側の全キーを出せる。MAPPING を直すときの参照用

### フリマは各アプリの画面から起こす

Yahoo!フリマ・ラクマ・メルカリは Moneytree の連携対象ではないため、
それぞれのアプリのマイページをスクショして値を起こす。
転記の仕組みは Moneytree 由来のものと同じで、MAPPING に行を足すだけ。

**記録するのは売上金のみ。** ポイント・PayPay残高・キャッシュは含めない。
画面には複数の数字が並ぶので取り違えに注意する。

| アプリ | 画面上の項目 | シートの行 |
|---|---|---|
| Yahoo!フリマ | 売上金 | `資産/フリマ/Payフリ（亮太）` |
| Yahoo!フリマ（明子） | 売上金 | `資産/フリマ/Payフリ（明子）` |
| ラクマ | 売上金 | `資産/フリマ/ラクマ` |
| メルカリ | 売上金 | `資産/フリマ/メルカリ` |

### 未確定な点

- **`三菱UFJ銀行 普通` を `三菱UFJ（亮太）` に暫定で割り当てている。**
  Moneytree の表示では名義が分からない。アプリ側で口座名を
  `三菱UFJ（亮太）` のようにシートと同じ表記へ変更するのが望ましい
- 未連携の口座がある。銀行は楽天2口座と三菱UFJの片方、
  カードは BICカメラSuica / ニッセンマジカル / JOSHIN / Tカードプラス。
  連携するか、使っていないならシートから行を落とすか決める
- Amex が「接続の更新が必要です」状態。再連携しないと残高が古いままになる
- 各カードの正確な締め日。`payment-reminder.gs` は 15日締め / 月末締めの
  暫定値で組んである
