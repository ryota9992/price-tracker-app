# Yahoo!フリマ 自動再出品ボット

出品した商品が売れたら、**同じ内容で自動的に再出品する**ローカル常駐ボットです。

半自動（承認してから出品）で始めて、慣れたら**設定1行を変えるだけで完全自動**に移行できます。処理の流れは両方とも同じで、最後に「承認を待つかどうか」が変わるだけです。

---

## ⚠️ 先に読んでください

- **Yahoo!フリマには出品用の公開APIがありません。** そのため、このボットは自分のアカウントにログインしたブラウザを自動操作（Playwright）して動きます。
- **自動化はYahoo!フリマの利用規約でグレー〜禁止に触れる可能性があり、最悪アカウント停止のリスクがあります。** 使うかどうかは自己責任で判断してください。リスクを下げるため、アクセス間隔の下限（10分）、ランダムな待ち時間、1日の出品上限、稼働時間帯の制限を最初から入れてあります。**これらを緩めるほど危険度は上がります。**
- Vercelなどのサーバーレス環境では動きません。**常時起動できるPC / Mac / VPS**が必要です。
- サイトのHTML構造は非公開で、しかも予告なく変わります。**初回は必ず `dryRun: true` のまま動作確認してください。**

## セットアップ

```bash
cd bot
npm install
npx playwright install chromium   # ブラウザの取得（初回のみ）
cp config.example.json config.json
```

### 1. ログイン

```bash
npm run login
```

ブラウザが開くので、**自分でYahoo! JAPAN IDにログイン**してください（2段階認証もここで）。終わったらターミナルで Enter を押すと、セッションが `data/auth.json` に保存されます。

> IDとパスワードをボットに渡す設計にはしていません。`data/auth.json` はログイン済みCookieそのものなので、**絶対に他人に渡さない・コミットしない**でください（`.gitignore` 済み）。

### 2. サイトの構造に合わせる（重要）

Yahoo!フリマのDOMは公開されていないため、**セレクタの初期値は推測**です。そのままでは動かない可能性が高いです。サイト依存の情報はすべて `selectors.json` の1ファイルに隔離してあるので、**コードは触らず、ここだけ直せば追従できます。**

```bash
npm run inspect
```

`data/inspect/` に各画面のスクリーンショット・HTML・セレクタ候補（`*.hints.json`）が保存されます。それを見ながら `selectors.json` を埋めてください。各項目は**候補の配列**で、上から順に試して最初に見つかったものが使われます。

特定の商品ページも見たいときは `npm run inspect -- <商品ID>`。

### 3. 監視する商品を登録

```bash
npm run track -- --all          # 出品中の商品をまとめて登録
npm run track -- <商品URL>       # 1つだけ登録
```

このとき、タイトル・説明・価格・状態・配送設定・**画像ファイル**をローカルに保存します（`data/images/`）。再出品はこの保存内容から行うので、**売れて商品ページが消えても再出品できます**。

### 4. 動作確認（dryRun）

```bash
npm run once     # 売却チェックを1回だけ実行
npm run list     # 現在の状況を表示
```

`dryRun: true` の間は、**出品フォームに入力するところまでやって「出品する」は押しません。** 入力後の画面が `data/images/<商品ID>/sell-form.png` に保存されるので、内容が正しいか目で確認してください。

### 5. 常駐させる

```bash
npm run watch
```

監視ループと承認画面が同時に立ち上がります。承認画面は **http://localhost:8787**（localhostのみ・外部には公開されません）。

## 半自動 → 完全自動への移行

`config.json` の2つのスイッチだけです。

| 段階 | `dryRun` | `autoApprove` | 動き |
|---|---|---|---|
| ① 最初はここ | `true` | `false` | 売れたら通知 → 承認画面でボタンを押すと**入力だけして止まる**（スクショで確認） |
| ② 出品を実際に試す | `false` | `false` | 売れたら通知 → 承認画面でボタンを押すと**本当に出品される** |
| ③ 完全自動 | `false` | `true` | 売れたら**確認なしでそのまま再出品** |

①→②→③と進めるのがおすすめです。②で数回うまくいくのを見てから③にしてください。③にしても処理内容は同じで、承認待ちで止まらなくなるだけです。

## 動き方

```
出品中の商品を監視（15分±5分ごと）
   ↓ 一覧に「売却済み」を検知
保存しておいたスナップショット（文章・価格・画像）を読み出す
   ↓
  autoApprove: false → 承認待ち＋通知 → 承認画面でボタン → 出品
  autoApprove: true  → そのまま出品
   ↓
出品成功したら、新しい商品を自動で監視対象に引き継ぐ
   ↓
（また売れたら最初に戻る）
```

新しく出品された商品が自動で監視対象になるので、**一度登録すれば売れるたびに回り続けます**。

## 安全装置

| 仕組み | 内容 |
|---|---|
| **緊急停止** | `data/STOP` という空ファイルを作ると即座に停止。削除すると再開 |
| **1日上限** | `maxRelistsPerDay`（初期値20件）を超えたら止まる |
| **稼働時間** | `activeHours`（初期値8〜23時）の外では動かない |
| **アクセス間隔** | `pollIntervalMinutes` は10分未満に設定できません。毎回ランダムなブレを加算 |
| **操作間隔** | `minSecondsBetweenActions`（初期値8秒）で人間らしい速度に |
| **失敗時** | 連続5回失敗すると監視を停止。画面のスクショを残します |
| **dryRun** | 出品直前で止めて内容を確認できる |

## 通知

`config.json` の `notify.webhookUrl` に Slack か Discord の Incoming Webhook URL を入れると、「売れました」「再出品しました」「失敗しました」が飛びます。Macならデスクトップ通知も出ます。

## テスト

```bash
npm test
```

Yahoo!フリマを模したローカルのモックサイトを立てて、登録 → 売却検知 → 承認待ち → dryRun → 実出品 → 新商品の引き継ぎ → 1日上限 → 緊急停止 まで一通り検証します（21項目）。

**このテストは自分で書いたモックに対するものなので、「本物のYahoo!フリマで動く」ことの保証ではありません。** 検証しているのはロジック（状態遷移・安全装置・スナップショットの受け渡し）であって、セレクタの正しさではありません。セレクタは `npm run inspect` で実物に合わせてください。

## うまく動かないとき

| 症状 | 対処 |
|---|---|
| `出品した商品一覧ページを開けませんでした` | `selectors.json` の `urls.myListings` を `inspect` の結果に合わせる |
| `出品カードを認識できませんでした` | `myListings.itemCard` を修正 |
| タイトルや価格が空 | `itemDetail.*` を修正 |
| 売却を検知しない | `myListings.soldBadge.textCandidates` に実際のバッジ文言を追加 |
| 出品フォームが埋まらない | `sellForm.*` を修正。`data/images/<ID>/sell-form.png` で入力状態を確認 |
| ログインが切れる | `npm run login` をやり直す。数週間ごとに必要になります |

ログは `data/bot.log` に残ります。
